# Prepare a GEEZ gig promotion

**Purpose:** turn a confirmed gig into a clear, on-brand promotion package
without losing booking provenance or scheduling the same content twice.
**Trigger:** a gig is confirmed, its public details change, or its promotion
window opens. **Owner:** GEEZ; ChatGPT assists with evidence, preparation and
authorized execution. **Canonical tool roles:** [Tool ownership](tool-ownership.md).

**Default finish:** a reviewable package in the existing private DJ Clone chat
or content plan. Preparing this package does not itself publish anything.
If the user already authorized specific scheduling/publication, carry that
authorization through; do not ask them to approve the same action again.

## 1. Gather the minimum brief

Read the original confirmation and the relevant NoxReach gig or GEEZ Social
booking record. Keep each fact linked to its source. Do not create another
booking or assume the two tools synchronize.

| Input | Check |
| --- | --- |
| Event, venue and city | Correct public names and original confirmation |
| Event date, doors and GEEZ set time | Distinguish doors from show/set time; missing set time stays unknown |
| Booking status | Confirmed, not merely an inquiry, candidate or fee proposal |
| Announcement permission | Any embargo or organizer restriction; ask only if unresolved |
| Ticket destination and promoter handles | Verify the actual link and handles; no guessed collaborators |
| Audience and objective | Fan attendance, promoter proof, or both as separate pieces |
| Assets and existing promotion | Approved artwork/exports, exact versions, prior posts and active jobs |

Do not put fees, contact details, booking identifiers or private asset paths
in this public playbook. Keep the completed brief with the existing private work.
If sources conflict, flag the specific conflict and ask one precise question
before scheduling or writing a definitive public claim about it. Continue
independent asset review while waiting. Omit nonessential unknowns rather than
inventing them.

## 2. Anchor the promotion plan

Fetch the current Europe/Berlin date and time. Start any resulting schedule with:

> Today is [weekday] DD.MM.YYYY, Europe/Berlin.
> Current local time in Europe/Berlin: HH:MM CET/CEST.

If the clock cannot be fetched, request confirmation of the date, weekday and
Berlin time; do not produce a schedule. List planned days sequentially with
explicit dates, and label every time **Berlin time (CET/CEST)**. Record the
event's own local time separately when abroad. Check any date/weekday conflict.

Inspect existing Zernio jobs and published history for the correct account
before choosing slots. Existing approved jobs take priority over a fresh plan.
Factor in other confirmed gigs, recent posts and nightlife viewing windows;
use account evidence when available and label untested timing as a proposal.
Do not invent a universal best posting time.

Use **Story → Reel → Carousel → Aftermovie** as the default editorial sequence,
not a quota. State which pieces are worthwhile, which are already covered,
and which are omitted. An aftermovie requires actual post-event footage.
Never imply that historical footage is from the upcoming or latest event.

## 3. Select assets and prepare copy

Read the available DJ Clone Personal DNA and approved editing instructions.
Flag missing sources instead of treating the local mirror as complete.
Prioritize performer presence, groove, dancefloor movement, controlled tension
and release. Keep captions calm, short and specific to the event; avoid generic
hype, overposting and unsolicited “available for bookings” copy.

- Reuse approved exports first. Identify the exact version; do not replace an
  approved cut with a rejected or experimental alternative.
- Before proposing a layout, inspect width/height, orientation, subject position
  and audio. State what is feasible and why. Specify the output ratio and exact
  crop coordinates/dimensions when cropping; do not promise impossible framing.
- For suitable short-form footage, 9:16 at 1080×1920 is an established GEEZ
  target, not permission to crop every source that way. Preserve original
  landscape framing when portrait would lose hands, decks or important context.
- Follow existing logo/end-card guidance. When using the brand line, preserve
  its order: **Tech House Drive. Disco Groove. Tribal Energy.**
- Preserve source files and approved masters. Editing or paid/cloud processing
  is a separate action unless already authorized. Use only tracks explicitly
  supplied by the user; do not infer or substitute music from filenames.
- Separate fan copy (event/date/location/ticket action) from promoter proof
  (performance and room response). Keep collaborator invitations distinct from
  accepted collaborations; never promise acceptance.

Check the intended upload route's current media requirements before export or
submission. Verify the export's duration, dimensions, codecs, audio, opening,
gestures, ending and branding. State whether checks were metadata-only, sampled
frames or full playback/listening; do not claim checks that were unavailable.

## 4. Assemble one reviewable package

Keep this table in the existing private content plan or project chat:

| Piece / objective | Fact sources | Approved asset/version | Caption / CTA | Account and format | Berlin date/time | Publishing route | Existing job / status | Blocker or next action |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

Include cover selection, collaborators and any first comment or special Reel
setting only when intended. Label each piece **proposed**, **approved**,
**draft**, **scheduled**, **published**, **failed** or **manual action needed**
according to evidence. An approved package is not a scheduled job.

Present the exact package for any genuinely outstanding publication decision.
If the current task is preparation only, finish here with the unresolved items
and the next action. Do not create placeholder jobs to make the plan look complete.

## 5. Authorized publishing handoff

| Tool | Action |
| --- | --- |
| NoxReach / GEEZ Social | Read booking context from the owning record; changes remain separate authorized booking actions |
| Scheduler | Optional planning cards/reference; never a second scheduling entry point |
| Zernio | Inspect the live queue, then create or update the specifically authorized automated job |
| Native Instagram | Complete manual Story stickers, ticket links, overlays or Reel shares where required by the verified route |

Immediately before any publishing write, recheck the live account queue and
published history. Match the event, exact asset/version, caption and intended
slot; a different card title does not make it different content. Reuse an
existing authorized job where appropriate. If the same asset is intentionally
reused in another format or slot, record the reason rather than silently treating
it as new. Verify the tool's stored timestamp resolves to the agreed Berlin time.

For a native Story, provide the approved asset, overlay copy, exact ticket URL,
intended Berlin slot and named manual action. Preview stickers against faces,
hands, decks and logo. Mark it **manual action needed** until execution is
observed or the user reports completion; identify reported evidence as such.

## 6. Verify, record and recover

- After scheduling, read the job back: account, media, caption, format, stored
  time and status must match. Record its reference in the existing private plan.
- After publication, check provider outcome and the platform permalink. Confirm
  the visible post matches the intended asset/copy; verify manual Story links
  where accessible. A successful queue submission alone is not publication.
- If publication is in the future, report **scheduled; outcome verification
  pending**. Do not claim success or install a monitoring automation implicitly.
- If a request times out or the result is ambiguous, inspect the same job and
  platform history before retrying. Do not submit through Scheduler as a fallback.
- If booking details change, identify affected jobs and public pieces. Prepare
  corrections; edit/cancel/send only within the user's authorized scope.
- If a route or source is unavailable, retain the approved package and name the
  blocker. Do not silently swap accounts, assets, tools or dates.

## Completion criteria

Preparation is complete when booking facts are sourced, the exact assets/copy
and routes are identified, proposed timing is explicit, the existing queue was
checked (or access is named as a blocker), and each piece has a next action.
Publication is complete only for pieces with observed or clearly attributed
reported outcomes. Record actual available results against the chosen objective;
do not infer ticket sales from views or invent unavailable metrics.

## Ask ChatGPT

> Prepare promotion for [confirmed gig] using the Rackagentur “Prepare a GEEZ
> gig promotion” playbook and Tool ownership map. Read the available DJ Clone
> context, original booking confirmation, approved assets, and current account
> queue. Produce one sourced promotion package with explicit Berlin dates/times,
> exact asset versions, publishing routes, duplicate checks and unresolved items.
> Preserve already approved jobs. This request is preparation only; do not publish,
> schedule, message promoters, or change booking records.
